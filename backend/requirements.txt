# EXACT pins (==) — the versions this tree was actually tested against
# (audit fix: this file used to SAY "pinned / reproducible builds" while
# every entry was a version RANGE, so two builds a week apart could ship
# different dependency sets).
#
# Plan V4.3 — direct pins alone don't lock TRANSITIVE deps. The Docker
# images install from requirements-lock.txt (full resolution, --require-
# hashes); this file stays the human-readable source for dev installs.
# To bump a dependency:
#
#   1. update the pin here AND in requirements.in
#   2. pip-compile --generate-hashes --strip-extras \
#        -o requirements-lock.txt requirements.in
#   3. pytest
#
# NOTE: saknussemm is NOT listed here — it is installed separately, and it
# must be installed WITH ITS VISION EXTRA. `packages/saknussemm` has not
# existed since the library left this repository on 2026-08-16 and its tree was
# flattened; the instruction below said otherwise for long enough that nobody
# could have followed it.
#
#   pip install 'saknussemm[vision] @ git+https://github.com/maribakulj/saknussemm@main'
#   pip install -r backend/requirements.txt -r backend/requirements-dev.txt
#
# REFRESHING an environment that already carries the library needs
# `--force-reinstall --no-deps` on the first line. `@main` moves and the
# library's `__version__` does not move with it (0.9.0 before and after
# `CorrectionResult.undeliverable_files` landed), so pip can call the
# months-old copy satisfactory and say nothing. The same trap has a
# Docker shape: the image layer is cached on its command string, hence
# the `SAKNUSSEMM_REF` build arg in both Dockerfiles.
# `app/jobs/engine_contract.py` turns a stale engine into a startup
# refusal instead of an AttributeError at the end of a paid run.
#
# The `[vision]` extra is Pillow, and it is not optional for this backend:
# `VisionEditProducer` crops each line from the page scan, and without Pillow
# every vision job fails at the first crop with ModuleNotFoundError — measured,
# not supposed. A text-only install is a backend that silently cannot run half
# of what it offers.
#
# CI follows this two-step install. The Dockerfiles do too. See
# CONTRIBUTING.md for the local-dev recipe.
